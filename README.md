# CarCare Studio — PWA Edition 1.0

## النشر على GitHub Pages
1. فك ضغط الحزمة.
2. أنشئ مستودع GitHub باسم `carcarestudio-pwa` (مستودع مستقل عن التطبيق الأصلي).
3. ارفع **محتويات** الحزمة إلى جذر المستودع مع مجلد `icons` كاملًا. يجب أن يكون `index.html` في الجذر، لا داخل مجلد إضافي. ملف `.nojekyll` اختياري ويمكن إنشاؤه من واجهة GitHub إذا أخفاه نظام الملفات.
4. من Settings → Pages → Build and deployment اختر Deploy from a branch ثم `main` و`/(root)` واضغط Save.
5. افتح الرابط الذي يظهر في Pages بعد نجاح النشر عبر HTTPS.

## التثبيت على iPhone
- افتح الرابط في Safari، ثم مشاركة → إضافة إلى الشاشة الرئيسية. فعّل Open as Web App إن ظهر، ثم إضافة.
- افتح التطبيق من الأيقونة مع الإنترنت أول مرة. من الإعدادات تحقق من رسالة جاهزية العمل دون إنترنت، ثم اختبر وضع الطيران.

## البيانات والنسخ الاحتياطي
- البيانات والمرفقات تُخزّن محليًا في IndexedDB؛ ليست مخزنة على GitHub ولا تتزامن بين الأجهزة.
- بيانات نسخة HTML السابقة لا تنتقل تلقائيًا إلى نطاق الاستضافة. صدّر ملف `.carcare` من النسخة السابقة واستورده من إعدادات PWA، وكرر النقل إلى أي جهاز آخر حسب الحاجة.
- احفظ نسخًا احتياطية في تطبيق Files أو مكان آمن. قد يحذف النظام تخزين الموقع؛ لا تحذف التطبيق أو بيانات المتصفح قبل النسخ الاحتياطي.
- تذكيرات الصيانة داخل التطبيق فقط؛ لا توجد إشعارات مجدولة في الخلفية. تقارير PDF تعمل عبر الطباعة/الحفظ حسب دعم النظام.
- لم يُعدّل تطبيق iOS الأصلي. توافق النقل إليه يحتاج اختبارًا على جهاز حقيقي.

## التطوير المحلي والتحديثات
- شغّل خادمًا محليًا من جذر الحزمة: `python -m http.server 8000`، ثم افتح `http://localhost:8000/`.
- لا تختبر Service Worker بفتح index.html كملف محلي مباشرة. تحتاج HTTPS أو localhost.
- عند تعديل ملفات التطبيق بعد النشر، غيّر VERSION في sw.js إلى إصدار جديد قبل رفعها. بعد تحميل الإصدار الجديد، أغلق جميع نوافذ التطبيق وافتحه مرة أخرى حتى يتفعّل التحديث. لا يحذف التحديث قاعدة IndexedDB.
- لا ترفع ملفات النسخ الاحتياطية الشخصية إلى المستودع العام.
